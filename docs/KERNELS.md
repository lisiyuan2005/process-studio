# 仿真内核：Slab (DeviceFlow) 与 OpenVDB

有两个内核，建工作区时选，之后不能换（两者的几何表示不同，结果互不可读）：

- **Slab (DeviceFlow)**：工程的几何是**精确的多边形板层（slab）堆叠**，由并入的 DeviceFlow 0.2.0 内核计算，不是网格上的场。默认内核。
- **OpenVDB (level set)**：每种材料一个**窄带符号距离场**，存在 OpenVDB 网格里，界面落在体素中心之间（亚体素精度）。代价随体素数增长，与形状无关：斜面、曲面、多次湿法刻蚀之后的复杂前沿，不会像 slab 那样让多边形顶点越积越多。见下面「OpenVDB 内核」一节。

原来还有一个自带的 level set 内核（均匀网格上的符号距离场）。它在 `0.9.8` 之后从 main 删掉了，代码留在 `archive/levelset` 分支上。用它建的工程打开时会被明确拒绝，并说明该去哪个版本打开，不会被悄悄换到别的内核上跑。

## Slab 内核能做什么

| | Slab (DeviceFlow) |
| --- | --- |
| 几何表示 | 精确多边形板层堆叠；没有网格 |
| 精度参数 | 保形沉积沿高度的行走步长（z）和平面内圆弧的弦高（XY）；垂直刻蚀、平面沉积和 CMP 与这两个数无关，任何分辨率下逐位相同 |
| 沉积 | 保形、平面；厚度可以直接给，也可以给周期数×每周期速率（ALD）或时间×速率；可带掩膜：先整片生长，再逐层只留下气体经开口到得了的空间里的那部分（见下面的「光刻胶」），等价于理想 lift-off：开口内的侧壁有膜，开口通到的、埋在被覆盖区域下面的孔道里也有膜，光刻胶占着的地方没有。留下的膜还必须是从气体碰得到的表面上长出来的：被光刻胶盖住的墙不长膜，所以开口停在下一级台阶立面前、离它不到一个膜厚时，开口里不会多出一片贴着立面立起来的膜 |
| 刻蚀 | 垂直（`directional_fraction` = 1）或各向同性（0），不支持中间值 |
| 氧化 | 露出表面向内一层原地变成氧化物，按各材料的 rate 比例消耗，不模拟体积膨胀 |
| 翻片 | 整片翻过来：原来的背面朝上，接下来的步骤做在背面。体积逐位不变，横向按翻转轴镜像（绕 y 翻则 x 镜像） |
| CMP | 平面截断，对所有材料一视同仁 |
| 掩膜 | 无掩膜、Quick Sketch、GDS |
| 3D 视图 | 直接输出几何三角面，按面着色：平面就是两个三角形，用顶点法线插值会在对角线上显出暗纹 |
| 快照 | `.dfz`，DeviceFlow 的 ZIP 状态存档 |

## 两档膜模型（fidelity）

两个内核都有这两档，含义相同；顶栏精度按钮旁边的按钮切换，默认 **simplified**：

- **simplified**：膜的拐角是直角，每个平面一段，不按分辨率采样，快得多。
- **detailed**：膜的拐角是圆角，沿高度按分辨率采样。

各档的结果分开保存，切回去不用重算。命令行是 `process-studio fidelity [detailed|simplified]`。原来还有第三档 voxel（体素），已经去掉：用它存的工程打开时按 simplified 显示，旧的体素结果不再读取，删步骤时一并清掉。

## 高度约定

界面上的高度：晶圆表面在 z = 0，衬底向下延伸到工程窗口的 `zMin`，沉积向上生长。

DeviceFlow 自己的坐标是从 z = 0 的地板向上生长的，所以内核把衬底建成 `|zMin|` 厚的一层，并在所有对外的高度上加回 `zMin`。改工程窗口的 z 范围就改了衬底厚度和上方的余量。CMP 的 `target_z`、截面的纵轴、3D 的包围盒都按工程高度给出，不需要用户换算。

## 不能做的事会明确报错

内核不会把做不到的工艺近似成别的东西。以下情况直接失败并说明原因：

- `directional_fraction` 不是 0 或 1；
- 沉积模式是 `directional`、`evaporation` 或 `fill`；
- 刻蚀既没有目标深度也没有时间。

CMP 步骤如果带了材料列表或停止层，会在日志里说明该内核的 CMP 不区分材料，然后按平面截断执行。

cpp/vdbcore/                        OpenVDB 内核的 C++ 部分（nanobind）
benchmarks/nand10/                  NAND10 基准

`runner.py`、`protocol.py` 只通过这个接口工作，不判断内核 id。注册表（`kernels/__init__.py`）留着是因为工程要记住自己用的是哪个内核（好拒绝别的），以及某份构建漏装依赖时要能报告而不是崩掉。

## 依赖


内核需要 `shapely` 和 `trimesh`，两者已在 `pyproject.toml` 的依赖里，打包脚本也会一起收进 worker。缺少它们时注册表里就没有可用内核，`describe` 的 `kernels` 是空的并说明原因，不会假装可用。

**各向同性刻蚀为什么慢，以及慢在哪**：profile 真实工程第 31 步（10 nm 的 SiCON 湿法刻蚀，253 个 slab），589 s 里几乎没有一处是"算得多"，全是"同一件事算了很多遍"：每一步问 3,295 次膨胀而只有几十个是不同的（127 s）、每个集合的并集重算（95 s）、`_assemble` 每条边建一个 LineString（560 万次）、板层归一里每对相邻 slab 都做一次边界叠加（50 s）、`clean` 把 GEOS 刚吐出来的合法多边形再修一次再并一次再裁一次（12,000 次）。这些全部去掉之后同一步 **589 s → 279 s**，七种材料体积逐位不变，401 个高度切片上几何差的总面积 6.4e-8 µm²（窗口是 0.09 µm²，也就是网格量级，正是 harmonize 声明的"几何最多移动一个网格步"）。

**还试过两条路，都量了，都退回来了**——记在这里免得下次再试：

- **把简化版前沿的 XY 角也做成直角**（mitre join）：诱人之处是直角膨胀完全不加顶点，前沿就不会一步步复杂下去，实测 state 从 21 个 slab/11,896 个顶点降到 12 个/4,251 个。但**目标材料多刻掉了 37%**：直角拐角比真实前沿多伸出 0.41 r，每步都多伸一次。这不是简化，是算错。
- **把前沿按容差简化掉多余顶点**：从每步深度的 2% 扫到 20%，**顶点反而变多**（11,896 → 15,230），slab 也变多。原因很具体：相邻采样共用同一个 reach 靠的是"环对环完全一致"，简化过的 reach 和邻居不再一致，于是每个采样都独立成为一个 slab。

所以前沿的顶点会一步步累积（真实一步从 205 个涨到 2,994 个）这件事**目前是方法本身的性质**，不是可以顺手抹掉的。真正的下游账单也在这里：第 27 步一个湿法刻蚀把 state 从 35 个 slab/44,685 个顶点变成 249 个/932,203 个，后面每一步沉积、刻蚀和建网格都在为这个买单。


## 单步分辨率

沉积、刻蚀、氧化步骤可以有自己的分辨率（步骤参数 `resolution`，单位 µm；界面上 Add a parameter → Resolution (this step)，命令行 `steps set 步骤 --set resolution=0.001`）。不设就用工程的分辨率。

- **slab 内核**：这一步的 z 步长和 XY 弧线弦高都换成它，下一步回到工程的（每一步都会重新设，所以前一步的设置不会带过来）。


## OpenVDB 内核

每种材料是一个窄带符号距离场（内部为负，带宽每侧 3 个体素），所有材料共用一套体素格点，互不重叠。一步工艺把用到的材料读成稠密数组、在数组上算、再写回 OpenVDB 网格；3D 视图用 OpenVDB 的 `volumeToMesh` 出网格（平滑着色），截面和俯视图按距离场双线性插值上色。C++ 部分在 `cpp/vdbcore/`（nanobind 绑定），由 `scripts/build_vdbcore.py` 编译进 `src/process_studio/kernels/openvdb/`。

### 精度旋钮与膜模型是两回事

- **体素尺寸**：顶栏的 nm 按钮。对 OpenVDB 来说它就是体素边长（预设 10 / 5 / 2 nm，新工程 10 nm）。界面放在体素之间，所以膜厚、刻蚀深度能落到体素的几分之一；但比约两个体素还薄的结构分辨不出来。体素减半，体素数变成 8 倍，时间和内存同比增长。窗口最多 4000 万个体素，超了会在对话框里直接提示，运行时也会拒绝。
- **simplified / detailed**：和 slab 一样，是膜和湿法前沿的形状。simplified 用圆柱做结构元（XY 圆、z 方向直角）：膜在台阶顶上直角收边；detailed 用球（精确欧氏偏移，由表面网格算距离场），拐角是半径等于膜厚的圆角。湿法刻蚀/氧化：detailed 用快速行进法算测地到达时间（绕障碍物走），simplified 用圆柱前沿分步推进（每步最多 1.5 个体素，所以也绕障碍物、不穿透），每步重新求距离场以免前沿漂移。
- 步骤自带的 `resolution` 参数对这个内核不起作用（体素格点是工程级的），会在日志里说明。

### 各工艺的定义（与 slab 内核一致）

| 工艺 | OpenVDB 的做法 |
| --- | --- |
| 保形沉积 | 固体并集按膜厚膨胀（球或圆柱），减去原固体 |
| 平面沉积 | 保形膜再截到“天空看得见”的柱子：该点上方整列没有固体 |
| 带掩膜沉积 | lift-off：开口外的天空空间是光刻胶；膜只留在气体经开口到得了的空间里，并且只从气体碰得到的表面长出来（被胶盖住的墙不长膜） |
| 垂直刻蚀 | 每一列从顶往下，材料 m 的一段长度 h 花费 h / rate(m) 的时间；空隙免费；速率为 0 或没列出的材料是停止层。每体素 8 个子采样，界面在体素内插值定位 |
| 各向同性刻蚀 | 从“活”的空隙（与外界连通、不被光刻胶占据）出发，按各目标材料的速率推进；非目标材料是墙，前沿只能绕过去；密闭空腔不是源 |
| 氧化 | 同一个前沿，消耗掉的区域原地变成产物（不模拟体积膨胀）；产物不能同时是被氧化的材料 |
| 翻片 | 高度 z → top + floor − z；绕 y 翻则 x 镜像，绕 x 翻则 y 镜像；堆叠上方的空气不带过去 |
| CMP | 平面以上全部去掉，不区分材料 |

窗口是封闭的：四面侧壁和底面都不是表面，晶圆在窗口外按边缘那一列/最底那一层继续延伸（所以窗口边缘不会长膜，也不会从边缘开始刻蚀；一个打穿整个堆叠的孔底部保持开口）。代码里留了周期边界（`Lattice.periodic`），界面上还没有开放。

### 多材料界面的处理

几种材料在同一处相接时，各自的距离场在交界线附近都接近 0，直接取最小值当“固体”会在交界线与外表面相交处留下一道亚体素的沟（膜会顺着沟长、截面上看是一条缝）。内核用外侧的距离值重算这些点的内部距离（`field.solid_field`），截面和 3D 着色也按这个修正过的固体场判断哪里是空的。

### 与 slab 内核、NAND10 基准的对比

- 同一套流程（沉积/掩膜孔刻蚀/保形膜/湿法/氧化/CMP/翻片/lift-off）两个内核的截面图，5–10 nm 体素下不同像素都在 1% 以内，差别只是边缘一两个像素。
- `benchmarks/nand10/run.py`：10 条字线的 3D NAND 单元（ONO、打底、沟道、孔芯、狭缝、SiN 置换、W 填充回刻），沿三条探测线与解析值比较界面位置。2 nm 体素、detailed：最大误差 0.52 nm，总耗时约 60 s；simplified 约 40 s（W 相关的检查值按圆角算，simplified 的直角膜本来就不同）。同一基准 slab detailed 约 15 s、误差 0.13 nm——层状、竖直为主的结构正是 slab 的强项；OpenVDB 的优势在曲面和反复湿法之后的复杂前沿。

### 依赖与打包

- 需要编译好的 `_vdbcore`（OpenVDB、TBB、nanobind）以及 scipy、scikit-fmm（`pip install -e ".[openvdb]"`，再 `python scripts/build_vdbcore.py`）。缺任何一个，注册表把它列为不可用并给出原因，slab 照常可用；新建工作区的内核卡片里会显示原因。
- 发布构建目前只在 **macOS** 包含它：CI 用 Homebrew 的 OpenVDB 编译核心，PyInstaller 把它连同依赖的动态库一起打进 worker。Homebrew 的库针对构建机的 macOS 版本编译，更老的系统上这个内核会报告不可用而不是让程序起不来。Windows 版暂不包含（卡片上写明“目前只为 macOS 构建”）。
